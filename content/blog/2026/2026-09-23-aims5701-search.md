## 1. Agents that plan ahead

### 1.1 Reflex agent：只看现在

Reflex agent 或 reactive agent 根据当前 percept 选择动作，也可能保留一点记忆或当前世界状态的模型，但它不真正考虑动作的未来后果。它回答的问题更接近：

> 现在看到了什么？面对这个状态，我应该立刻做什么？

例如，开车时看到前面有一辆车，最直接的 reflex 行为是刹车。它只需要根据当前观察作出反应，并不需要先模拟“换道之后会不会超过前车、再并回原车道”。

老师把这个问题和 rational agent 联系起来：一个 reflex agent 在某些简单、稳定的环境中当然可能是 rational 的；但 rational 并不等于永远只做即时反应，而是要看它是否能在当前目标下选择最合适的行为。

### 1.2 Planning agent：先问 what if

Planning agent 会问：

> 如果我采取这个动作，接下来会发生什么？

它需要一个关于世界如何变化的模型，也就是 world model；还需要明确的 goal test，才能判断一系列动作是否真的完成任务。它不是只考虑世界现在是什么样，而是考虑在不同动作下世界将会变成什么样。

在前面的开车例子中，planning agent 可以同时模拟两种方案：

1. 继续留在当前车道并减速；
2. 换到右侧车道，超过前车，再并回原车道。

它先在内部的世界模型中展开这两种可能的后果，再按照到达目的地的时间、距离或安全性选择方案。这就是搜索问题的直觉来源：我们不是直接猜一个动作，而是在候选行动序列中寻找可行或最优的计划。

### 1.3 Optimal planning 和 complete planning

老师专门区分了两个容易混淆的词。

- **Complete planning**：只要最后能完成任务，就算找到了一个 solution。比如从 A 到 B，任意一条能到达 B 的路线都可以。
- **Optimal planning**：不仅要完成任务，还要按照预先定义的 cost 找到最低成本方案。比如在总距离、总时间或能耗意义下找到最优路线。

所以，找到一条路只能说明算法是 complete；只有当这条路确实达到最低 cost，才能说明它是 optimal。

### 1.4 Planning 和 replanning

Planning 通常发生在行动开始之前：根据当前状态和已知的世界模型先制定一条路线，然后执行它。Google Maps 给出从 A 到 B 的最快路线就是一个例子。

但现实世界可能在执行过程中变化：发生交通事故、道路拥堵，或者某条路临时关闭。原先基于旧状态得到的计划就可能不再是最优，甚至不再可行。这时 Agent 需要根据新的状态重新计算计划，这就是 replanning。

因此，规划并不是“算出一次路线后永远照做”。它依赖于对环境的预测；当预测被现实打破时，就需要重新搜索。

## 2. 把任务写成 Search Problem

### 2.1 Search problem 的五个组成部分

课件把一个搜索问题定义成以下组件：

1. **State space**：所有可能的状态集合；
2. **Successor function**：从当前状态出发有哪些 action，每个 action 会产生什么后继状态，以及 action 的 cost；
3. **Start state**：行动开始时所处的状态；
4. **Goal test**：如何判断当前状态已经达到目标；
5. **Solution**：一串把 start state 变成某个 goal state 的 actions，也就是一个 plan。

这里说的是“a goal state”而不是“the goal state”，因为一个问题可能存在多个目标状态。比如在迷宫中，任何一个苹果都可以作为目标；Agent 只要到达其中一个即可。

### 2.2 Pac-Man 的 route-finding

老师使用 Pac-Man 作为贯穿整节课的例子，但强调必须先明确任务边界。如果现在只想解决“从当前位置走到指定方格”，那么：

- state 是 Pac-Man 的位置 \((x,y)\)；
- actions 是向北、南、东、西移动；
- successor 是执行一步合法移动后到达的新位置；
- goal test 是 Pac-Man 是否已经到达目标方格；
- path cost 是执行过的 unit-cost moves 数量。

这个问题里，食物和鬼的位置可以暂时不放进 state，因为它们不会影响“是否到达这个目标方格”这一任务。如果把任务改成“吃完所有食物”，问题就变了：state 不仅要记录位置，还要记录哪些食物仍然存在，goal test 也改成“是否已经没有食物剩下”。

如果任务进一步变成“吃完所有食物，同时让鬼保持 frightened”，state 还要记录 power pellet 是否剩余、鬼的 scared time 等信息。任务不同，planner 必须记住的东西也不同。

### 2.3 World state、search state 和 abstraction

真实环境的 world state 可以包含所有细节：每个物体的位置、方向、剩余资源、时间和其他动态变量。但一个具体的搜索任务通常不需要保留全部信息。

Search state 只保留会影响以下内容的细节：

- 当前有哪些合法 actions；
- 采取 action 后会进入什么 future state；
- 是否满足 goal；
- 后续路径的 cost。

例如在 Pac-Man 中，如果任务只是到达目的地，只记录位置就够了；如果任务是吃完所有食物，就必须额外保存食物的布尔地图。这个过程就是 abstraction：把和当前任务无关的真实世界细节删掉，降低搜索空间。

课件给了一个数量级对比。假设有 120 个位置、30 个食物位置、2 个鬼，每个鬼有 12 个位置，并且 Pac-Man 有 4 个朝向：

- 完整世界表示大约有 \(120\times 2^{30}\times 12^2\times 4\) 个状态；
- 只做 route finding 时，只需要 \(120\) 个位置；
- 做 eat-all-dots 时，大约需要 \(120\times 2^{30}\) 个状态。

这说明“怎么表示 state”本身就是算法设计的一部分。不是状态记录得越完整越好，而是要保留完成当前任务所必需的信息。

### 2.4 Classical search 的假设

本节课的经典搜索模型建立在五个假设上：

1. **Fully observable**：当前状态完全已知；
2. **Deterministic**：一个 action 只有一个确定结果；
3. **Discrete**：状态和 action 是离散的；
4. **Static**：规划过程中环境不会自行变化；
5. **Known**：action 的效果已知。

现实世界经常不满足这些条件：传感器可能看不全、动作可能有随机性、物理状态可能连续、环境会在规划期间变化、动作后果也可能未知。因此，这一讲不是在说所有 Agent 都可以直接套经典搜索，而是在建立一个清晰的理想化模型。

## 3. State-space graph、search tree 和 frontier

### 3.1 State-space graph

State-space graph 是搜索问题的数学表示：

- node 是抽象后的 world configuration，也就是一个 state；
- edge 表示一个 action 及其结果；
- goal test 对应一个或多个 goal nodes。

在 state-space graph 中，每个 state 只出现一次。如果从不同路径回到了同一个 state，仍然只保留一个图节点。对于很小的问题，可以把完整图画出来；但真实问题通常太大，无法全部存进内存，所以它更多是一个理解问题结构的抽象。

### 3.2 Search tree

Search tree 是“如果采取不同计划，会发生什么”的 what-if tree：

- root 是 start state；
- child 是执行一个 successor action 后的结果；
- 每一个 tree node 不仅对应一个 state，还对应一条到达这个 state 的 action sequence。

因此，同一个 state 在 search tree 中可能出现很多次，因为不同路径可能到达同一状态。图中的 state 是唯一的，树中的 node 则代表“路径 + state”。

这也是 search tree 可能无限膨胀的原因。图本身可能并不大，但如果存在循环，搜索树会把同一个状态沿不同长度的路径重复展开。

### 3.3 Search node 和 frontier

搜索不会一次性建立完整的树，而是维护一个 frontier，也叫 fringe。它保存目前已经生成、但还没有继续展开的 partial plans。

一个 frontier entry 至少需要记录：

| 字段 | 含义 |
| --- | --- |
| state | 当前配置 |
| parent | 到达当前 node 的前一个 search node |
| action | 从 parent 到当前 node 的动作 |
| path cost \(g\) | 从 start 到当前 node 的累计成本 |

每一步搜索都可以拆成三件事：

1. 从 frontier 中选择一个 node；
2. 检查它是否满足 goal test；
3. 如果没有达到目标，就展开它，把 successors 加回 frontier。

不同的搜索算法，核心框架其实相同，主要差别是“下一次从 frontier 里选谁”。

### 3.4 怎样评价搜索算法

老师给出四个评价标准：

- **Completeness**：只要 solution 存在，算法是否一定能找到；
- **Optimality**：返回的 solution 是否是最低 cost；
- **Time complexity**：需要展开多少搜索节点；
- **Space complexity**：需要在 frontier 或其他结构中保存多少信息。

这些性质不能脱离问题假设单独讨论。例如 BFS 在每条边 cost 都相同的时候保证最低成本，但当边 cost 不同，BFS 只保证动作数量少，不保证总 cost 最小。

如果 branching factor 是 \(b\)，最大深度是 \(m\)，搜索树的节点数大致为：

\[
1+b+b^2+\cdots+b^m=O(b^m),\qquad b>1.
\]

深度越大，最底层节点通常占据绝大部分数量，所以搜索策略的主要目标就是尽量少展开不必要的分支。

## 4. Uninformed Search：没有目标方向信息

Uninformed search 不使用关于目标距离的额外知识。它只根据已知的 frontier、路径和 cost 来决定展开顺序。

### 4.1 Depth-First Search：LIFO stack

DFS 每次展开最深的 frontier node，使用 LIFO stack。假设展开 B 后按顺序插入 C、D，那么 stack 的下一个取出顺序是 D、C；后插入的节点先被处理。

DFS 的优点是空间相对节省：它主要沿一条路径深入，同时保留回溯所需的分支。但它有两个明显问题：

1. 如果先进入一条很深、但没有目标的分支，可能花很久才回来；
2. 如果图中存在 cycle，tree search 会不停地生成更深的重复节点，目标可能永远等不到。

在 branching factor 为 \(b\)、最大深度为 \(m\) 时，课件给出的时间复杂度是 \(O(b^m)\)，空间复杂度大致是 \(O(bm)\)。DFS 在最大深度有限并且处理 cycle 时可以找到解，但它不保证找到最浅或最低成本的解，因此通常不 optimal。

### 4.2 Breadth-First Search：FIFO queue

BFS 每次展开最浅的 frontier node，使用 FIFO queue。展开 B 后把 C、D 放入队列，C 会在 D 之前被取出；它会先完成当前层，再进入下一层。

如果最浅的 solution 深度是 \(s\)，BFS 会展开深度小于 \(s\) 的节点，时间和空间大致都是 \(O(b^s)\)。只要 solution 存在且浅层有限，BFS 是 complete。

当所有 action 的 cost 都相同，BFS 也是 optimal，因为动作数量最少就等于总 cost 最低。但如果不同道路有不同距离：

- 路线 A 可能只需要 4 个动作，但总 cost 是 15；
- 路线 B 可能需要 5 个动作，但总 cost 是 11。

BFS 会偏好 4 个动作的路线，却没有找到最低 cost 的路线。因此，“最少步数”和“最低代价”必须分开。

找到 goal 后，可以通过 parent 指针恢复完整路径。例如从 G 回溯到 F、R、E、S，再反转得到：

\[
S\rightarrow E\rightarrow R\rightarrow F\rightarrow G.
\]

### 4.3 Iterative Deepening

Iterative Deepening 用逐渐增加的 depth limit 重复运行 depth-limited DFS：

1. 先运行深度上限为 1 的 DFS；
2. 找不到就重新运行深度上限为 2 的 DFS；
3. 继续增加上限，直到找到目标。

它会重复探索靠近根部的节点，但完整搜索树的大部分节点位于最深层，因此在很多情况下重复成本相对有限。它试图结合 BFS 找浅层解的性质和 DFS 较低的空间占用，是一个典型的 time–space trade-off。

### 4.4 Uniform-Cost Search：按累计 cost 选择

UCS 把 frontier 组织成 priority queue，每次移除累计路径 cost \(g(n)\) 最小的 node：

\[
g(\text{child})=g(\text{parent})+c(\text{parent},\text{child}).
\]

UCS 和 BFS 的关键区别是，BFS 看深度或 action 数量，而 UCS 看从 start 到当前 node 已经付出的真实 cost。

老师用一个会出现更便宜新路径的例子说明 frontier 更新。假设 D 原来通过 S–A–C 到达，累计 cost 是 7；后来从 S–B–D 到达，cost 只有 5，那么 D 仍然在 frontier 中时，必须把它的记录更新为：

- path cost：\(7\rightarrow 5\)；
- parent：\(C\rightarrow B\)；
- queue priority：\(7\rightarrow 5\)。

UCS 的停止条件也很重要：**不能在 goal 第一次被加入 frontier 时停止，必须等 goal 成为 priority queue 中最小的项并被取出时停止。**

在 Romania route-finding 例子中，Bucharest 可能已经以 \(g=450\) 进入 frontier，但 Pitesti 仍然有 \(g=317\)，它后面可能接出一条总 cost 为 418 的路线。因此必须继续搜索，直到 Bucharest 以当前最小 frontier cost 被 dequeue。

UCS 的优点是，在边 cost 非负时能够返回最低成本解；缺点是它没有任何 goal direction，只会按已付出的 cost 向外扩张。低成本的路径可能暂时把搜索带离目标，所以它会在很多方向上探索。

## 5. Informed Search：利用目标方向信息

### 5.1 Heuristic function

如果只看已经付出的 cost，算法不知道“离目标还有多远”。Informed search 引入 heuristic function \(h(n)\)，估计从当前 state \(n\) 到最近 goal 的剩余 cost：

\[
h(n)\approx \text{cost from }n\text{ to a goal}.
\]

它必须针对具体搜索问题设计。常见例子包括：

- 网格路径上的 Manhattan distance：只允许横向和纵向移动，并忽略障碍；
- Euclidean distance：允许直接沿直线走，并忽略障碍和移动规则；
- Romania 地图中城市到 Bucharest 的 straight-line distance。

启发式不是实际剩余成本，而是一个 estimate。它有用的地方在于给搜索提供目标方向，但它是否保证 optimal，要看它有没有高估真实剩余成本。

### 5.2 Greedy Best-First Search：只看未来

Greedy Best-First Search 的 priority 是：

\[
\text{priority}(n)=h(n).
\]

它每次选择“看起来离目标最近”的节点，因此会很快朝目标方向走。Romania 例子中，从 Arad 开始，它会优先选择 straight-line distance 最小的城市。

但 Greedy 完全不考虑已经走过的 cost \(g(n)\)。它只看未来，不看过去。某个节点虽然看起来离目标很近，却可能是通过一条非常昂贵的路线到达的；如果继续相信低 \(h\)，Greedy 就可能被一条“看起来正确”的路径带到错误目标或昂贵路线。

### 5.3 A*：把过去和未来加起来

UCS 只看过去的真实成本：

\[
\text{priority}=g(n).
\]

Greedy 只看未来的估计成本：

\[
\text{priority}=h(n).
\]

A* 把两者合起来：

\[
f(n)=g(n)+h(n).
\]

其中：

- \(g(n)\) 是从 start 到当前 node 已经付出的真实 cost；
- \(h(n)\) 是从当前 node 到 goal 的估计剩余 cost；
- \(f(n)\) 是经过当前 node 的完整路线总 cost 的估计。

老师在课上逐步算了一个小例子。展开 A 后，B、D、E 的数据如下：

| Node | \(g(n)\) | \(h(n)\) | \(f(n)=g(n)+h(n)\) |
| --- | ---: | ---: | ---: |
| B | 2 | 6 | 8 |
| D | 4 | 2 | 6 |
| E | 9 | 1 | 10 |

因此 A* 选择 D，因为它的 \(f=6\) 最小。它不是单纯选择已经走得最少的 B，也不是单纯选择看起来离目标最近的 E，而是比较“已经花掉的 + 预计还要花的”。

### 5.4 A* 什么时候停止

这是本节课很容易考、也最值得记住的细节：

> A* 不能在 goal 被 enqueue、加入 frontier 时停止；必须等 goal 被 dequeue、从 priority queue 中取出时停止。

老师用一个小图说明这一点。假设：

- \(S\rightarrow B\rightarrow G\) 很快生成 goal，实际 cost 是 5；
- frontier 中还有 \(A\)，而 \(S\rightarrow A\rightarrow G\) 的实际 cost 是 4；
- 当前 \(f(A)=4\)，已经生成的 goal 的 \(f(G)=5\)。

虽然 G 已经进入 frontier，但 A 的 \(f\) 更小，所以 A* 必须先展开 A，找到 cost 4 的路线，不能因为“已经看到 goal”就提前宣布胜利。

换句话说：

1. enqueue goal 只说明“找到了一条到 goal 的候选路线”；
2. dequeue goal 才说明“它当前已经是 frontier 中最有希望的路线”；
3. 在 heuristic 满足 admissibility 的条件下，这时才能保证它是最优解。

## 6. Admissibility：A* 保证最优的关键

### 6.1 一个高估 heuristic 为什么会出错

老师给了一个非常直接的反例：

- 从 S 到 A 的真实已付出 cost 是 \(g(A)=1\)；
- A 到目标的真实最小剩余 cost 是 3；
- 但我们错误地设置 \(h(A)=5\)；
- 另一条已经到达目标 G 的路线 cost 是 5，且 \(h(G)=0\)。

于是：

\[
f(A)=g(A)+h(A)=1+5=6,
\]

\[
f(G)=g(G)+h(G)=5+0=5.
\]

A* 会先取出 G，并返回 cost 5；但真实最优路线是经过 A，cost \(1+3=4\)。错误来自 \(h(A)\) 高估了剩余成本，让一个真正更好的计划看起来太差，被困在 frontier 里。

### 6.2 Admissible heuristic 的定义

令 \(h^*(n)\) 表示从 \(n\) 到最近 goal 的真实最低成本。一个 heuristic \(h\) 是 admissible 的，如果：

\[
0\leq h(n)\leq h^*(n).
\]

它可以低估，但不能高估，所以也被称为 optimistic heuristic。低估会让某些较差路线暂时显得有希望，增加搜索工作；但它不会把真正的最优路线错误地排除掉。

老师把两种情况说得很直白：

- **Pessimistic / inadmissible**：估计太大，可能把好路线挡在后面，破坏 optimality；
- **Optimistic / admissible**：估计不超过真实成本，可能慢，但不会因为 heuristic 把最优路线压掉。

Manhattan distance 和 Romania 地图中的 straight-line distance 都是 admissible 的典型例子，因为它们都删除了一些限制：

- Manhattan distance 忽略障碍，但仍然保留只能横向/纵向移动；
- straight-line distance 甚至允许直接穿过障碍或沿对角线走。

放宽限制后得到的路径只会更便宜，不会比原问题更贵，因此它可以作为原问题最优成本的 lower bound。

### 6.3 Relaxed problem 如何产生 heuristic

如果原问题要求避开墙、遵守道路或一次只能移动一个相邻 tile，那么可以构造一个更容易的 relaxed problem：

1. 删除一个或多个限制；
2. 在限制更少的问题上求最优解；
3. 把 relaxed optimum 当作原问题的 heuristic。

因为原问题的任何可行解在 relaxed problem 中仍然可行，而 relaxed problem 还可能多出更便宜的解，所以：

\[
h_{\text{relaxed}}(s)
\leq
h^*(s).
\]

这就是 admissibility 的来源。课上老师强调，在实际使用 A* 时，最难、也最重要的工作往往不是写 priority queue，而是设计一个足够有信息量、同时不高估的 heuristic。

### 6.4 8-puzzle：错误位置数和 Manhattan distance

8-puzzle 有 8 个 tile 和一个空格，每次只能把一个相邻 tile 滑入空格，每步 cost 是 1，目标是把所有 tile 排成目标布局。

第一种 heuristic 是 **misplaced tiles**：

- 忽略 tile 之间的阻挡；
- 允许一个 tile 直接被放到目标位置；
- 每个位置错误的 tile 至少需要 1 步；
- 因此 \(h\) 可以取错误 tile 的数量。

第二种 heuristic 是 **total Manhattan distance**：

- 仍然忽略其他 tile 的阻挡；
- 但对每个 tile 计算它到目标位置的横纵距离；
- 再把所有 tile 的距离加起来。

课上示例中，misplaced-tile heuristic 是 8，而 Manhattan distance 是：

\[
3+1+2+\cdots=18.
\]

18 比 8 更接近真实剩余 cost，所以通常能指导 A* 少展开一些节点。课件中的平均展开节点数量也体现了这一点：UCS 使用 \(h=0\) 时最多，misplaced tiles 较少，Manhattan distance 更少。

但“heuristic 数值更大”不能简单理解成“任何情况下都更好”。必须同时满足：

1. 它仍然是 admissible 的；
2. 计算它所花的时间没有超过节省下来的搜索时间。

如果一个 heuristic 恰好等于真实剩余成本 \(h^*(n)\)，搜索方向当然最强；但计算 \(h^*\) 本身可能已经等价于把原问题完整解决。因此实际使用时要权衡 heuristic evaluation cost 和 search expansion cost。

如果 \(h_1,h_2,\ldots,h_m\) 都是 admissible 的，可以取：

\[
h(n)=\max\{h_1(n),h_2(n),\ldots,h_m(n)\}.
\]

因为每个输入都不超过 \(h^*(n)\)，最大值仍然不超过 \(h^*(n)\)，同时它至少不会比任何单独的 heuristic 弱。

## 7. A* 最优性证明：录音里的逐步推导

这是录音最后重点讲的部分。目标是证明：

> 如果 \(h\) 是 admissible 的，A* tree search 会先取出最优 goal，再取出次优 goal。

设：

- \(A\) 是一个最优 goal，路径成本为 \(C^*\)；
- \(B\) 是一个次优 goal，路径成本大于 \(C^*\)；
- \(h\) admissible；
- 假设 B 已经在 frontier 上，马上可能被取出；
- 从 start 到 A 的路径上，必然还有一个 ancestor \(n\) 在 frontier 上；这个 \(n\) 也可能就是 A 自己。

现在要证明 \(n\) 一定会在 B 之前展开。

### 7.1 第一步：证明 \(f(n)\leq f(A)\)

因为 \(n\) 位于通往 A 的最优路径上：

\[
g(n)+h^*(n)=C^*.
\]

admissibility 给出：

\[
h(n)\leq h^*(n).
\]

两边加上 \(g(n)\)：

\[
g(n)+h(n)
\leq
g(n)+h^*(n).
\]

左边就是 \(f(n)\)，右边就是 \(f(A)\)，因为 A 是 goal，且 \(h(A)=0\)：

\[
f(n)\leq f(A).
\]

### 7.2 第二步：证明 \(f(A)<f(B)\)

因为 A 是最优 goal，B 是次优 goal：

\[
g(A)<g(B).
\]

对于 goal，heuristic 到自身的剩余成本是 0：

\[
h(A)=h(B)=0.
\]

所以：

\[
f(A)=g(A)+0=g(A),
\]

\[
f(B)=g(B)+0=g(B).
\]

因此：

\[
f(A)<f(B).
\]

### 7.3 第三步：合并不等式

把前两步连起来：

\[
f(n)\leq f(A)<f(B).
\]

所以 \(f(n)<f(B)\)。A* 每次选择 frontier 中 \(f\) 最小的 node，因此 n 必然先于 B 被展开。

### 7.4 第四步：从 ancestor 推到最优 goal

通往 A 的路径上，最靠近 root 的 ancestor 先被展开；展开它之后，下一个 ancestor 会进入 frontier。由于同样的逻辑继续成立，所有 ancestors 都会在 B 之前被展开，最后 A 也会在 B 之前被取出。

因此，只要 heuristic admissible，A* 不会先返回次优 goal。它可能因为 heuristic 太弱而展开很多节点，但不会牺牲最优性。

这个证明把 A* 的核心直觉说清楚了：heuristic 可以乐观，但不能悲观。它可以让差路线暂时获得较小的 \(f\)，却不能让真实最优路线被错误地赋予一个过大的估计。

## 8. 这节课讲到哪里

PDF 的 outline 还列出了 Graph Search。后续课件页继续讨论 closed set、重复状态、A* 的 consistency，以及为什么一致的 heuristic 可以让永久关闭一个 state 变得安全。但现有录音在上面的 A* optimality proof 处结束，所以我把这些内容作为课件中的后续部分保留，没有写成今天录音已经讲完的内容。

今天这节课对我最重要的不是背下 DFS、BFS、UCS、Greedy 和 A* 的名字，而是看清楚它们其实都共享同一个框架：

1. 定义 state 和 goal；
2. 从当前 node 生成 successors；
3. 把 partial plans 放进 frontier；
4. 用不同 policy 选择下一个 node；
5. 在合适的停止条件下恢复 solution path。

算法之间的差别，主要就是 frontier 的排序依据：

| 方法 | frontier 的选择依据 | 是否使用目标方向 |
| --- | --- | --- |
| DFS | 最新插入的 node | 否 |
| BFS | 最早插入的 node | 否 |
| UCS | 最小 \(g(n)\) | 否 |
| Greedy | 最小 \(h(n)\) | 是 |
| A* | 最小 \(g(n)+h(n)\) | 是 |

这也解释了为什么这节课虽然叫 Search，却不是 Search Agent 工程课。它是在先把“Agent 如何在一个形式化世界模型里规划行动”这件事讲清楚；ReAct、Tool Calling 和现代 Agent 的具体实现，可以看作建立在更复杂、更多不确定性的环境上。
