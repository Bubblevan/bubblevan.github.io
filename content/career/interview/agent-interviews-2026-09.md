## 一、整理版：高频考点与复习地图

### 1. 项目讲述与深挖：先把“事实链”讲完整

每个项目准备一张事实卡，按下面顺序讲，所有数字都要能说明来源：

1. **业务问题与用户**：谁遇到什么问题，为什么原流程不够。
2. **输入、输出与主链路**：Query/事件如何进入，经过哪些确定性代码、模型或工具，最终产出什么。
3. **本人边界**：自己写了什么、改了什么、只是调研了什么；团队/导师/AI 分别贡献什么。
4. **关键取舍**：为什么选该架构/模型/框架/存储，不选什么替代方案；取舍对应的约束是什么。
5. **状态与失败路径**：超时、模型拒答、工具失败、数据缺失、并发冲突、断连、恢复分别发生什么。
6. **验证证据**：测试集怎么来、基线是什么、指标怎么算、样本量多大、失败案例是什么；区分离线实验、真实用户和生产数据。

对“是否适用于真实业务”“是否能自动修复”“为什么不用现成框架”等追问，先划清当前实现范围，再给出生产化差距和分阶段方案，不把计划说成已落地。

### 2. Agent / Harness / Workflow / 多 Agent

- 能从用户请求讲到最终回复：输入规范化/意图识别 → 路由或计划 → Agent loop（模型决策、工具执行、观察结果）→ 状态更新 → 停止条件 → 返回结果。
- 能比较 **Workflow 与 ReAct**：前者流程明确、可控、易测；后者在工具选择与步骤上更灵活，但有不确定性、成本和循环风险。很多系统是确定性工作流中嵌入局部 Agent，而不是二选一。
- 解释多 Agent 的必要性时落到边界、并行、上下文隔离或专业能力；同时说清路由成本、协调开销、共享状态冲突和故障传播。若单 Agent 足够，就不应为了“多智能体”而拆分。
- Harness 不止是 Prompt：还包含运行循环、工具/权限、状态与上下文、调度、持久化、重试恢复、观测、评测和资源治理。准备一个读过源码/自己追过调用链的具体例子。
- 多 Agent 通信要说清消息协议/字段、共享状态所有权、任务状态机、幂等键、超时与取消；A2A 是互操作协议概念，不等于系统里任意 Agent 间通信都自动安全可靠。

### 3. 状态流转、持久化、并发与恢复

- **LangGraph 类图编排**：State 定义共享状态；节点读写状态；边决定后继；并行分支汇合；Reducer 合并多个节点对同一字段的更新；Checkpoint 持久化状态以支持中断后恢复。答题时区分“图内状态更新”和“跨进程可靠任务队列”。
- **Task DAG**：节点需有 pending/running/succeeded/failed/cancelled 等状态和依赖；只有依赖满足才可运行。失败后按错误类型重试、跳过可选分支、回滚/补偿或暂停等待人工；下游不得把失败当成功。记录 attempt、deadline、幂等键和可重放输入。
- **并发防重**：数据库唯一约束/条件更新/CAS、租约、心跳和 fencing token 解决不同层次的问题。乐观锁冲突要有限重试、退避并设上限；高冲突时切换串行化/队列/更细粒度锁，防止重试放大延迟。
- **消息与持久任务**：任务执行和 SSE 连接生命周期分离；客户端断连不必然取消后端任务。保存事件游标/任务状态，重连补发或查询最终状态；明确用户取消与网络断连的语义。
- **自恢复**不是无限重试：分类可恢复/不可恢复错误，设最大尝试次数、总 deadline、退避、熔断和人工接管阈值；产生可解释的最终状态与审计记录。

### 4. 上下文、Memory、Skills 与缓存

- 短期上下文保留近期对话和当前任务状态；长期记忆需有提取、更新、过期/淘汰、按用户/租户授权过滤和按需召回。当前明确指令优先于历史偏好。
- 对话压缩前识别必须保留的目标、约束、决定、未完成事项、引用和状态；保留原始记录或可检索来源，允许重要信息回查。工具输出可按 schema 截断/字段裁剪；错误码和证据优先保留。
- 说明压缩触发阈值如何从模型上下文上限、预留输出 token、历史增长与质量评测确定，不把“32 轮/某个百分比”当成通用答案。
- **Skill / Tool / MCP**：Tool 是可执行能力及参数契约；Skill 通常是可按需加载的任务说明/流程/领域知识；MCP 定义客户端与工具/资源服务之间的互操作协议。不同产品语义有差异，按具体实现解释。
- 工具多时使用元数据筛选、分层发现、渐进加载完整 Schema，并处理 Schema 未加载却需要参数的回退；动态工具加载还要关注提示词前缀稳定性和缓存命中。
- Prefix Cache 依赖相同前缀；把稳定系统提示和常用 Schema 放前面，动态/低频工具按需加载。不要为缓存命中牺牲必要上下文或权限隔离。

### 5. RAG、检索与评测

- **链路**：文档解析/清洗 → 结构感知切分与元数据 → embedding/索引 → Query 处理 → 过滤/多路召回 → 融合与重排 → 上下文组装 → 生成与引用 → 评测/反馈/增量更新。
- 分块要解释粒度与边界：段落/标题路径/父子块、重叠、表格/代码处理；使用父子块时说明检索命中子块后如何回取父级上下文。按语料结构和问答粒度做验证，而非只给固定 token 数。
- 向量库、全文检索和混合检索按过滤、召回、运维、延迟、成本和已有基础设施选型；Redis、ES 都可能提供相关能力，不能只说“某一种最常见”。
- Top-K、停止检索、Query Rewrite、reranker 的收益要以离线集/线上日志验证；分开排查解析、切分、召回、排序、上下文截断、生成和知识时效。
- 指标口径：Hit@K 看相关目标是否进入前 K；Recall@K 看相关目标覆盖比例；MRR 对首个相关结果排名取倒数再平均。还要说明标注粒度、一个问题多个相关文档的处理方式，以及生成侧正确性/引用忠实度指标。
- Benchmark 需定义任务、输入、成功标准、难度分层、固定开发集/隐藏测试集、single-agent 对照、失败分类和重复运行策略。过程指标（工具调用、步骤、延迟、Token、恢复次数）与结果指标（成功率/正确性）同时看；做消融以归因收益。

### 6. 模型、SFT/RL 与基础算法

- 能解释 SFT 增加的行为能力，以及它与 Prompt、工具、更多检索轮数的作用边界；用消融/同预算对照区分收益来源。
- PPO/GRPO/奖励函数/收敛等训练题不要只背术语；结合目标、数据、采样、优化目标、评测和失败案例讲清。奖励覆盖度要说明为何与任务目标相关，防止奖励投机。
- 基础 AI：Attention 的 Q/K/V、缩放点积、Mask、multi-head、残差与归一化；分类/回归指标按业务错误代价选。若简历写了模型训练，准备数据规模、硬件、训练配置和复现证据。

### 7. 后端与系统设计

- **配额/计费**：流水唯一键与额度更新的原子边界；并发扣减用条件更新/CAS 或事务保证不超用；明确幂等、重试、对账和补偿。事务过大时用 Outbox/异步结算等方案，但说明一致性权衡。
- **数据库**：联合索引顺序结合等值/范围、选择性、排序、覆盖和实际执行计划；低基数字段并非必然不建索引。能读 EXPLAIN 并提出验证步骤。
- **缓存/Redis**：数据结构与适用场景、缓存穿透/击穿/雪崩、并发保护；压测报告吞吐、P50/P95/P99、错误率及数据规模。缓存语义与数据库事实源要分清。
- **HTTP/SSE/WebSocket**：按单向流式、双向交互、代理兼容和连接成本选；多轮上下文通常由服务端会话/客户端历史管理，不由连接本身自动保存。
- **进程/线程/协程、锁/信号量、GIL**：从共享状态与调度语义回答；结合 I/O 或 CPU 密集场景，不要仅背定义。

### 8. Coding 高频题

按面经出现频率优先练：LRU Cache（HashMap + 双向链表）、链表倒数第 N 个节点、K 个一组反转链表、环形链表、树层序遍历/对称二叉树、岛屿数量/最大面积。每题用目标语言在无提示下写出，覆盖空输入、边界和复杂度，并练 ACM 输入输出。

### 9. 复习闭环

把每题变成四栏：**我的事实/当前答案｜证据或代码位置｜追问与失败模式｜待补验证**。先挑自己简历上的项目追问，再补高频通用题；错题按“不会概念、记不清项目、方案不闭环、指标无口径、表达不清”分类，下一轮只针对薄弱点复测。
