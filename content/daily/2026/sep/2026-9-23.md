## 今日总结

### 简历项目方向重构

##### 我今天真正确认的原则

我把简历项目从“系统有什么模块”改成“岗位需要什么技术 → 我解决了什么问题 → 为什么这样设计 → 用什么实验得到什么结果”。56 次实验、261 个测试通过、`56/56 valid` 这类内容属于证据附录，不能直接冒充业务成果；简历真正要写的是准确率、恢复成功率、安全动作拦截率、吞吐、延迟、故障恢复时间和模型策略收益。今天除了 TraceSearch-R1 继续负责 Agentic RL / post-training，其余明确涉及的项目都按这个方向重构。

**StablePay｜Agent Commerce Runtime**

**背景**：面向 AI Agent 付费调用外部能力的执行控制、支付状态不一致与长任务恢复问题，基于 x402/Solana 构建可恢复的 Agent Commerce Runtime。

**结果占位**：Recovery benchmark 中 DeepSeek vs Rule 的 success `X→Y`、steps `A→B`；Guard unsafe reject `X`、valid accept `Y`、side-effect escape `0`；CloudWeGo 在 `N` concurrency 下 `Q req/s`、P95 `L ms`；Chaos 注入下 recovery `R%`、P95 TTR `T`，无 duplicate settlement。所有数字必须等 E1–E4 完成后再填写。

### AIMS5701：Search、规划与 A*

今天的 AIMS5701 第二课讲的是经典 AI 的 Search，不是现代 LLM Search Agent，也不是 ReAct。老师先区分了只根据当前状态行动的 reflex/reactive agent 和会建立 world model、预测行动后果的 planning agent，再把任务形式化成 state space、successor function、action cost、start state、goal test；录音里还特别强调了 optimal planning（找到最低成本方案）和 complete planning（只要找到可行方案）的区别，以及环境变化时需要 replanning。

后半节依次讲 DFS、BFS、Iterative Deepening、UCS、Greedy Best-First Search 和 A*。我今天最需要记住的是：BFS 只在每一步成本相同时保证最低成本，UCS 按累计成本 (g(n)) 选 frontier，Greedy 只看估计剩余成本 (h(n))，A* 才把过去和未来合起来，用 (f(n)=g(n)+h(n))。A* 找到目标节点时不能在 enqueue 时立即停止，必须等目标从 priority queue dequeue；否则 frontier 里可能还有总代价更小的路径。录音最后逐步证明了 admissible heuristic 下，最优目标会在次优目标之前出队。

课件后面还有 Graph Search、closed set 和 consistency，但现有录音在 A* 最优性证明处结束，暂不当作今天已经讲完。课程事务方面，老师的 office hour 是周四 16:00–17:00、SHB 814，默认线下；GS 的 office hour 本周稍后在 Blackboard 发布。录音没有听到 uReply 签到安排。
