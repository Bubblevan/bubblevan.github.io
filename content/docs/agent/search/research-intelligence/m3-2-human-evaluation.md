# M3.2 — Human Evaluation & Retrieval Stack Consolidation

M3.2 establishes a blind, resumable human judgment workflow for the frozen DEV-v1 retrieval candidate pool. It does not unlock M4. The benchmark is frozen only after every candidate in all 20 queries has an explicit 0/1/2 relevance judgment and the reviewer identity and time are recorded.

## Relevance guidelines

- **0 — Irrelevant:** the item does not answer the query or materially help investigate it.
- **1 — Relevant/useful:** the item contributes useful context, evidence, a method, or a source to follow.
- **2 — Directly important:** the item directly addresses the query or is a central result/example for it.
- Judge the content against the query. Do not reward recency, source prestige, popularity, personal author affinity, or where the retrieval system placed the item.
- Use the optional quality issue independently from relevance. `insufficient_metadata`, `broken_url`, `suspected_duplicate`, and `identity_problem` describe data quality; `none` means no issue was noticed. Do not turn a data-quality label into a relevance grade.
- If metadata is thin, use the canonical URL and visible source excerpt. If the item still cannot be judged, use grade 0 only when it is clearly irrelevant; otherwise leave relevance unanswered and add `insufficient_metadata`.

## Annotation and qrels source of truth

Argilla is an optional external UI. Configure `ARGILLA_API_URL` and `ARGILLA_API_KEY` in the process environment; an optional `ARGILLA_WORKSPACE` selects the workspace. Credentials are never command-line arguments, fields, metadata, qrels, or logs. `requirements-evaluation.txt` contains Argilla, `ir-measures`, and `ranx`; ingestion dependencies do not include them.

The hashed blind label pack is the candidate inventory. Its deterministic shuffled order is preserved on export. Every Argilla record is keyed by `(benchmark_hash, query_id, artifact_id)`, and existing records are left untouched during export so interrupted reviews can resume without duplicating records or overwriting judgments. Route, rank, score, retriever, fusion, and contribution metadata are prohibited from annotation payloads.

Imported judgments are validated against the pack's two hashes and exact query/artifact inventory. Partial imports remain draft qrels. Only a successful import, full coverage check, and explicit `eval-freeze` can create `dev-v1.json`. That frozen file is the benchmark and qrels source of truth for evaluation. Argilla remains the working annotation UI; it is not the evaluation source of truth after freeze.

The two blank Hugging Face Blog candidates may receive a display-only source name and Observation excerpt in the annotation UI. This context is not written back to the corpus, frozen label pack, or benchmark hash.

## Retrieval metrics and interpretation

Official DEV reports use `ir-measures` for Recall@5/10/20, RR@10, nDCG@10, P@10, and Judged@10. The repository's small metric implementation remains a diagnostic and is checked against a fixed graded qrels fixture at absolute tolerance `1e-9`. `ranx` produces independent aggregate and per-query reports and an RRF fixture comparison. With 20 queries, report paired per-query differences and uncertainty descriptively; do not claim statistical significance from a small DEV set.

After DEV freeze, B0–B4 are BM25, Dense, graph expansion, BM25+Dense RRF, and BM25+Dense+Graph RRF. Topic-only evaluation is reported separately for queries eligible for that route. Include per-query results, broad/specific and category slices, judged counts, and an error analysis. Treat poor results on this 20-query DEV as correctness and diagnosis signals, not permission to tune repeatedly. Keep HOLDOUT untouched.

## Feedback inventory and M4 decision

`feedback-stats` reports event/action counts, unique canonical Artifacts, time span, and per-Artifact counts without exposing query text or event bodies. Use the actual feedback volume to choose M4's ranking complexity. With very little feedback, start with deterministic content/profile ranking and diversity. Only evaluate LambdaMART/LightGBM when there are enough reviewed qrels. Consider contextual bandits only after online feedback is available, and multi-user recommenders only after the product has multiple users. This decision does not begin M4.

## Current operational gate

The local Argilla credentials are environment-only. If no server credentials are configured, use `eval-export-json` for the same blind records, review the exported responses, then `eval-import-json`. No labels may be inferred or generated by a model.
