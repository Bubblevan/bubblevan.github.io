1. 主题定位: 这期拆解 DeepSeek Harness，我主要演着几个关键模块往下讲，包含上下文和前缀缓存、工具和 Hook、Skill、记忆、多智能体、轨迹，最后再回到背后的插件机制。
2. 上下文组装: DSH 在每次请求前重新组装 system、工具定义和消息历史，并把影响模型的注入内容写进事件日志。
3. 上下文压缩: 它用规则裁剪超长工具结果，再在上下文窗口接近上限时让模型摘要较早的对话，同时保留完整日志。
4. 前缀缓存: 指令、运行状态和工具结果尽量采用追加式更新，减少改写请求前缀带来的缓存损失。
5. 工具与 Hook: 标准 Web 配置提供二十五个模型可见工具，DSH 更特别的 PTC 模式让模型通过代码组合工具；Hook 则负责审批、拦截和反馈。
6. Skill 与记忆: Skill 采用普通的按需加载，但没有解决海量 skill 的搜索路由；记忆底座负责记录和恢复，长期语义记忆交给插件。
7. 多智能体与轨迹: spawn、fork、可持续子 agent、workflow 和 Ralph 提供不同的编排方式，Trajectory 则把请求、工具、压缩和缓存信息完整展示出来。
