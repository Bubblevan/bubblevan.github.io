本站不同类型的文章应遵循以下分区规则。写新内容时先看这张表。

## 核心原则

本站用不同的分区承载不同生命周期的内容：

```text
随手记录想法/事件 → daily（收件箱）
    → 整理为结构化笔记 → docs（长期知识）
    → 输出为博客 → blog（历史快照）
    → 沉淀为项目资产 → projects（职业生涯素材）
```

## 各分区规则

### `daily` — 时间线捕获

**用途：** 低摩擦的当日记录。

- 今天发生了什么
- 简短观察和想法
- 值得记住的链接
- 快速任务笔记、临时项目日志
- 生活记录

**不应用于：** 稳定的技术解释、长期学习笔记、成熟的项目案例、面试回答、精选资源列表。

**规则：** Daily 是当天的"收件箱"。允许凌乱，但应包含足够的标记供以后抽取。

---

### `blog` — 有时效性的公开输出

**用途：** 带有历史背景的个人输出。

- 技术历程、项目里程碑
- 调试故事、研究或学习阶段总结
- 特定历史背景下的决策记录

**不应用于：** 应随着认知更新而覆盖的权威知识、原始日常片段、需长期维护的项目事实。

**判断标准：** 如果未来的修正应该**替换旧文**，放 `docs`。如果历史推理轨迹**应该保留可见**，放 `blog`。

---

### `docs` — 长期知识库

**用途：** 当前最佳认知。

- 当前的最佳理解和稳定技术解释
- 学习路径、可复用的实现笔记
- 架构原则、调试手册

**注意：** Docs 可以引用博客文章作为历史证据，但不应写成日记。

---

### `papers` — 论文阅读笔记

**用途：** 研究论文的阅读记录。

- 论文摘要、方法比较
- 数据集和基准笔记
- 研究分类

当某个概念成为长期知识时，在 `docs` 对应的主题索引页沉淀；论文笔记本身仍保留在顶层 `papers` 下。

## `docs` 当前信息架构

`docs` 按“读者要解决的问题”组织，不按“我当时在哪里学到的”组织：

| 目录 | 用途 |
|---|---|
| `learning` | Data、预训练、SFT、Distillation、RL，以及 CS336、PyTorch、Flow Matching 等学习主线 |
| `agent` | Agent loop、规划、推理、搜索和 Deep Research |
| `harness` | Runtime、工具调用、权限、Sandbox、MCP、Skills、Subagent，以及 OpenClaw/Pi/Claude Code/Hermes/dsh 等实现 |
| `embodied` | VLA、VLM、Navigation、World Model、Locomotion 等具身智能内容 |
| `full-stack` | 前端、后端、数据库、语言、网络和操作系统 |
| `web3` | 区块链相关学习笔记 |
| `undergraduate` | 本科课程笔记与实验报告 |
| `research` | 暂时保留的 AI4Science 等尚未迁入主地图的研究内容 |
| `meta` | 本站自身的规则和说明 |

`context`、`eval`、`systems` 是技术地图中的预留方向；只有出现稳定内容后才建立正式目录。

### CS336 的特殊规则

CS336 是一条课程主线，不按 Lecture 的主题拆散到不同目录。统一放在 `docs/learning/cs336/`：

```text
cs336/
├── lectures/   课程讲义和 Lecture 复盘
└── labs/       Assignment、Notebook 和实现实验
```

Lecture 可以被 `learning`、`agent` 或未来的 `eval`、`systems` 索引页交叉引用，但只保留一份正文。

### 目录深度

Hextra 会根据目录自动生成侧栏，建议知识页控制在 `docs/<主题>/<集合>/<页面>` 以内。课程、产品和工具名应使用简短的侧栏标题，完整解释放在页面正文中。

### URL 迁移

移动或重命名页面时：

1. 更新站内链接；
2. 给旧公开 URL 添加 Hugo `aliases`；
3. 不复制两份长期正文；
4. 只有在需要保留历史叙事时，才在 `blog` 留一篇指向新文档的短说明。

---

### `leetcode` — 面试算法练习

**用途：** 算法练习笔记。

- 题目笔记、解题模式、代码模板、复习状态

属于求职准备的一部分，但与项目 STAR 卡片分开，因为检索模式不同。

---

### `projects` — 长期项目资产

**用途：** 项目的持久化记录。包含公开展示和内部资产。

- 项目背景、架构、个人贡献
- 关键决策、证据和指标
- 复盘总结、面试用摘要
- 关联的博客和文档链接

`projects` 是项目的唯一主目录，涵盖公开展示页和内部资产（架构、决策、复盘等）。

---

### `career` — 求职资料

**用途：** 基于项目资产生成的求职材料。

- 项目卡片、STAR 故事、面试准备材料

**注意：** Career 内容是项目资产的**投影**，不是项目信息的源头。仓库公开时注意控制可见性。
